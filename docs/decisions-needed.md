## A. 구현이 막혀 있는 쟁점 (남은 API 14개)
제안대로 가도 되는 것은 "제안대로"라고만 답해도 된다. 근거는 팀 검토 문서(https://claude.ai/artifact/UxFFkRTkXhS4NJd6JjtSCi)다.

| # | 쟁점 | 결정할 내용 | 제안(권장) | 풀리는 API |
|---|---|---|---|---|
| A1 | 쟁점 2: 이메일 인증 토큰 | 지금 명세 예시는 이메일을 base64로 인코딩한 값이라 누구나 위조할 수 있다. | 추측할 수 없는 난수(UUID 등)를 Redis에 저장해 조회한다. 명세 예시도 고친다. | 이메일 인증 발송, 인증 확인, 비밀번호 재설정(3개) |
| A2 | 쟁점 3: refresh 재발급 경합 | 토큰이 사용자당 1개이고 재발급마다 교체돼서, 동시에 두 번 요청하면 두 번째가 실패해 로그아웃된다. | 서버에서 직전 토큰을 10~30초 유예한다(앱 수정 없이 해결). 또는 앱이 재발급을 한 번만 보내게 한다. | 토큰 재발급, 로그아웃(2개) |
| A3 | 쟁점 4: 탈퇴 닉네임 | 탈퇴 시 닉네임을 "탈퇴한 사용자"로 바꾸면 닉네임이 유일해야 한다는 제약과 부딪힌다. | 닉네임을 비우고(NULL) 응답에서 "탈퇴한 사용자"로 바꿔 보여준다. | 회원 탈퇴(1개) |
| A4 | 쟁점 5: 닉네임 없는 사용자 | 카카오 신규 가입자는 온보딩 전에 닉네임이 없다. 이때 쓸 수 있는 API 범위와 랭킹 노출이 정해져 있지 않다. | 온보딩 미완료자는 도착 인증을 막고 랭킹에서 제외한다. | 카카오 로그인, 온보딩 조회와 저장(3개) |
| A5 | 쟁점 6: 통계와 랭킹 날짜 기준 | 23:30에 인증하고 00:10에 사진 보너스를 받으면 어느 날로 셀지. | 통계와 랭킹은 포인트가 적립된 시각 기준, 활동 일지는 인증한 시각 기준으로 통일하고 명세에 적는다. | 통계, 사용자·장소·연속 참여 랭킹(4개) |
| A6 | 쟁점 7: 점수 출처 | 카테고리 기본 점수와 장소별 점수 중 어느 쪽이 우선인지. (지금은 장소 점수가 우선으로 구현함) | 장소 점수가 카테고리 점수를 덮는다고 명세에 적고, 명세의 "지역 축제 500점" 문구는 지운다(MVP에서 제외로 결정된 항목). | (이미 구현에 반영) 명세 문서 수정만 필요 |
| A7 | 쟁점 8: 사진 개인정보 | 사진 주소가 id로 추측되고, 사진의 위치 정보(EXIF)를 지우는 처리가 명세에 없다. | 저장 키를 랜덤으로 만들거나 서명된 URL을 쓰고, 업로드 때 EXIF를 제거한다. | 인증 사진 업로드(1개) |
| A8 | 사진 업로드 세부 | 재방문 인증에도 사진 한 장을 올릴 수 있게 할지(보너스는 첫 방문만). 로그인 시도 횟수 제한을 둘지. | 재방문도 한 장 허용하고 보너스는 0점. 로그인 시도 제한은 IP당 분당 횟수로 둔다. | 사진 업로드, 로그인 |

## B. 서버 정책 (현재 방식으로 구현되어 있고, 바꾸고 싶으면 알려주면 됨)
| # | 항목 | 지금 방식 | 선택지 |
|---|---|---|---|
| B1 | 포인트 합계 저장 | 포인트 내역의 합으로 계산(명세는 사용자 테이블에 누적 저장) | 현재 유지(권장, 어긋날 위험 없음) / 명세대로 저장(내역이 아주 많을 때 빠름) |
| B2 | 연속 참여 일수 | 미구현(명세는 도착 인증 때 갱신) | 완료 기록으로 계산(권장) / 저장하며 갱신 |
| B3 | 재방문 점수가 0점이 되는 경우 | 기본 점수가 1점이면 재방문이 0점인 내역이 생김 | 그대로 / 최소 1점 / 0점 내역은 만들지 않음 |
| B4 | 추천 정렬 | "안 가본 장소 우선 + 거리순"(명세는 안 가본 카테고리 우선) | 현재 유지 / 카테고리 단위로 변경 |
| B5 | 검색 반경 파라미터 이름 | `radius`(응답의 인증 반경 `radius`와 이름이 겹침) | 현재 유지(명세 그대로) / `searchRadius`로 변경(명세도 수정) |
| B6 | 성공 응답 문구 | 팀 저장소 문구("요청 성공"). 가입, 로그인 등은 명세 문구 | 현재 유지 / 전부 명세 문구로 통일 |
| B7 | 생성 시각의 시간대 | 서버 JVM 시간대(운영이 UTC면 UTC로 저장) | 현재 유지 / 한국 시간 기준으로 통일(권장) |
| B8 | 프레임워크 오류의 코드 형식 | 그 밖의 4xx는 `COMMON<상태>`(예: COMMON409) | 현재 유지(팀 방식) / 전부 COMMON400 |
| B9 | 잘못된 퍼센트 인코딩 쿼리 | 500으로 나감 | 400으로 바꾼다(권장) |
| B10 | 신뢰 경계 | 앱이 보낸 위치, 정확도, 모의 위치를 그대로 믿음(명세 허용) | 그대로 / 요청 횟수 제한과 이동 속도 검사 추가 |
