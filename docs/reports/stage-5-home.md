# 5단계 홈 "진행 중인 퀘스트" (feat/10-home-ongoing)

## 한 일
- 홈에 프로토타입의 "Ongoing Quests" 카드를 추가(내 포인트 카드 아래). 큰 개수 + 장소 줄 목록(카테고리 아이콘, 장소명, 카테고리 · 거리 · 보상 포인트, "진행 중" 칩, "포기").
- 데이터는 `QuestBook`(오늘 받은 퀘스트, KST 자정에 만료)에서 읽고, 장소 이름/카테고리/포인트/좌표는 `GET /places/{id}`로 풀어서 ViewModel에 캐시한다. 모르는 장소는 병렬로 읽고, 실패한 것은 목록에서만 빼고 기록은 남겨 다음 갱신 때 다시 시도한다. 서버서 `isCompleted`인 퀘스트는 목록과 기록에서 제거한다.
- 거리는 현재 위치가 있을 때만 계산하고(가까운 순 정렬), 없으면 "위치 권한 필요"를 보인다.
- 카드를 누르면 기존 `pendingPlaceId`로 지도 탭이 열리며 그 장소 상세 시트가 뜬다. "포기"는 `QuestBook.remove`로 즉시 목록에서 사라진다.
- 빈 상태: 안내 문구 + "지도에서 퀘스트 찾기" 버튼(지도 탭 이동). 첫 로딩 중에는 빈 상태 대신 로딩 표시.
- 홈 재진입 시 `start()`가 `refresh()`를 거쳐 퀘스트도 다시 읽으므로 지도에서 받기/포기/인증한 결과가 바로 반영된다.
- 서버/엔드포인트 변경 없음. 바뀐 파일: `HomeViewModel.kt`, `HomeScreen.kt`, `AppNav.kt`, 테스트 `HomeOngoingTest.kt`(신규), `HomeTest.kt`(companion 공개).

## 테스트
- 신규 8개(`HomeOngoingTest`): 목록+장소 데이터+거리, 빈 상태, 위치 없음, 자정 만료와 재진입, 지도 변경 반영, 서버 완료 제거, 조회 실패 처리, 포기.
- `testDebugUnitTest` 183개, `testReleaseUnitTest` 182개 모두 통과, `assembleDebug` 통과.

## 한계
- 퀘스트는 앱 안(SharedPreferences)에만 있어 다른 기기나 재설치(데이터 삭제) 시 보이지 않는다. 동기화하려면 서버에 수락 API가 필요하다.
- 프로토타입의 "3 / 5" 진행 막대는 하루 목표 수 정의가 없어 넣지 않았다(개수만 표시).
- 첫 진입 때 장소 상세를 처음 읽는 동안 잠깐 로딩 표시가 보인다(이후 캐시).
- 포기는 확인 대화상자 없이 바로 실행된다.
