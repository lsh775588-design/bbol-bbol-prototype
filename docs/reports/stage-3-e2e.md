# 3단계 E2E (에뮬레이터 + 새 서버) 보고서

- 일자: 2026-11-14. 앱: `feat/5-e2e` 디버그 빌드(`-PapiBaseUrl=http://10.0.2.2:8120/`), 서버: `port/integration`(local 프로파일, `JWT_EXPIRATION=75s`, `BBOLBBOL_LOCAL_FIXED_USER_ID=` 비움), AVD `Medium_Phone`, 위치는 경복궁(`geo fix 126.9780 37.5796`).

- 스크린샷은 `docs/screenshots/stage-3/`. 단말 갤러리 사진이 보이는 사진 선택기 화면은 개인 사진이 있어서 저장하지 않았다.

## 발견한 버그와 거슬리는 점
### 높음
1. **가입, 카카오 로그인 직후 온보딩 화면으로 가지 않고 홈으로 간다**(이메일 가입 2/2, 카카오 1/1 재현). 서버는 `isNewUser:true`를 정상 응답한다(curl로 확인). 앱을 껐다 켜면 온보딩이 나오므로 시작 시 확인 경로는 정상이다. 추정 원인: `ui/nav/AppNav.kt:111-118`의 `LaunchedEffect(loggedIn)`이 `collectAsState`로 읽은 `onboardingRequired`를 쓰는데, `markOnboarding`과 `saveTokens`가 연달아 일어나면 Compose 상태가 아직 갱신 전이라 false를 읽는 경쟁 상태로 보인다(`session.onboardingRequired.value`를 직접 읽으면 해결될 가능성). 카카오 신규 사용자는 닉네임이 없는 채로 홈에 들어간다(스크린샷 52, 53).
### 중간
2. **홈 화면이 탭을 오갈 때 다시 불러오지 않는다.** 도착 인증 후 홈이 1050P/4회로 남고(마이는 1400P/5회), 온보딩에서 닉네임을 정한 뒤에도 홈 인사말이 비어 있고 아바타가 "?"다(12, 42, 55). 추정 원인: `ui/home/HomeScreen.kt:69`의 `LaunchedEffect(Unit)`과 `HomeViewModel.start`가 한 번만 읽음.
### 낮음
3. 도착 완료한 장소(오늘 완료)에서도 "도착 인증하기" 버튼이 켜져 있다. 누르면 "오늘 이미 인증했어요" 오류가 난다(10, 11). 비활성화하면 좋다.
4. 틀린 인증 코드 입력 시 "남은 시도 4번"이 두 줄로 중복 표시된다(32).
5. 비밀번호 재설정 성공 문구("비밀번호를 변경했어요...")가 로그인 버튼 아래에 붙고, 로그아웃 후 다시 로그인 화면에 와도 계속 남아 있다(48, 50의 배경).
6. 세션 만료(재발급 실패)로 로그인 화면으로 돌아갈 때 이유를 알리는 문구가 없다(26).
7. 둘러보기 모드 초기 지도 줌이 너무 넓어 서울 전역에 핀이 겹친다(61). 지도 마커는 카테고리와 상관없는 기본 핀이고, 내 위치 표시가 보이지 않는다(06).
8. 지도 탭과 시스템 상태바가 겹쳐 시계 글자가 지도 위에서 흐리게 보인다(06).
9. 마이의 통계 타일 세 개의 높이와 글자 줄이 서로 다르다(13, 19).
10. 랭킹 단상이 참가자가 1~2명일 때 왼쪽으로 쏠린다(22, 25).
11. 로그아웃에 확인 창이 없다. 가입 화면의 "인증 코드 받기"는 빈 이메일에서도 눌린다(오류 문구만 나옴). 온보딩 "저장하기"는 아무것도 고르지 않아도 눌린다.
12. 홈 추천 카드의 장소 이름이 한 줄로 잘린다("청계천 광화문 구간(청계광..."). 의도라면 무시해도 된다(03).
13. 온보딩의 카카오 닉네임 제안이 앱 재시작 뒤에는 채워지지 않는다(54). 제안 값이 메모리에만 있다.

## 서버 로그로 확인한 것
- `POST /auth/reissue`: 마지막 서버 실행 중 6번. 토큰이 만료된 뒤 요청 3~4개가 한꺼번에 나가도 재발급은 1번이었고(04:49:28, 04:51:03) 직후 요청들이 모두 200이었다. 단일 비행(single-flight)이 동작한다.
- 서버 재시작으로 refresh token 저장소가 비면 앱은 로그인 화면으로 돌아갔다(크래시 없음).
- 오류 응답은 의도한 것뿐이었다: 400(틀린 코드), 401 두 번(틀린 비밀번호, 탈퇴 계정), 403(온보딩 미완료 도착 인증). 서버 ERROR 로그와 앱 크래시(`logcat -b crash`)는 없었다.

## 주의점(나중에 직접 만들 때 고려)
- 에뮬레이터 시계는 서버(KST)와 다르다(단말 7:4x, 서버 4:4x). 사진 마감 시각("05:39까지")과 기록 시각은 서버 기준 시각이 그대로 표시되므로, 단말 시간대와 맞춰 보여줄지 정해야 한다.
- 서버가 요청 로그를 거의 남기지 않는다. `DispatcherServlet=DEBUG`가 가장 쉬웠고, Tomcat access log는 켜도 파일에 기록되지 않았다(버퍼링 때문일 가능성, 해결하지 않음). 필터에서 걸러지는 401은 DispatcherServlet 로그에 안 보인다.
- 로컬 프로파일에서는 `BBOLBBOL_LOCAL_FIXED_USER_ID`를 비워야 401이 실제로 나온다. 서버를 재시작하면 인메모리 refresh token이 사라져 앱 세션이 모두 끊긴다.
- Compose 화면 상태 전달: 로그인/가입 직후 이동처럼 "상태를 바꾸고 바로 이동"하는 곳에서는 `collectAsState` 값을 믿지 말고 흐름의 현재 값을 직접 읽어야 한다(버그 1).
- 탭 화면은 탭에 다시 들어올 때 갱신 규칙(재진입 시 새로고침, 도착 인증 같은 변경 이벤트 후 무효화)을 처음부터 정해 둬야 한다(버그 2).
- adb 자동화: `adb input text`는 ASCII만 되고 `|` 같은 문자는 기기 셸이 해석하므로 `adb shell "input text '...'"`처럼 통째로 따옴표로 감싼다. Git Bash는 `/sdcard/...`를 윈도 경로로 바꾸므로 `adb push`에는 `MSYS2_ARG_CONV_EXCL='*'`와 윈도 경로(`cygpath -w`)가 필요하다. 사진 선택기(시스템 UI)는 기기 갤러리를 그대로 보여주므로 스크린샷이 개인 사진을 담지 않게 주의한다. 갤러리의 맨 위 칸이 방금 푸시한 파일이다.
- Compose 화면은 텍스트가 `uiautomator dump`에 잘 잡히지만, 버튼 상태(활성/비활성)는 덤프로 알 수 없어 스크린샷으로 봐야 했다.
- 개발용 토큰 지름길(가입)은 이메일을 먼저 올바르게 입력해야 동작한다(조용히 실패해 헷갈림).
- 서버 쪽 배움: 가입 응답과 카카오 응답이 `isNewUser`를 내려주므로 앱은 그 값에 의존한다. 이메일 가입 후 온보딩을 강제할지 정책이 필요하다(지금은 도착 인증 때 COMPLETION4031로 막는다).
