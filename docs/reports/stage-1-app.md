## 한 일

### 앱 (`feat/1-app`)
- `app/`에 Kotlin Android 프로젝트를 직접 작성했다(단일 모듈, 패키지 `com.bbolbbol.app`). 안드로이드 스튜디오 템플릿이 없어 Gradle 파일을 손으로 썼다.
- 기술: Jetpack Compose(Material3), Retrofit 3.0.0 + kotlinx-serialization, OkHttp 4.12.0, Navigation Compose, EncryptedSharedPreferences(토큰 저장), osmdroid 6.1.20(OpenStreetMap, API 키 불필요). AGP 8.13.0, Kotlin 2.2.20, Compose BOM 2025.09.00, Gradle 8.14.3, minSdk 26, compile/target SDK 36.
- 화면: 로그인, 회원가입(이메일·닉네임 실시간 중복 확인, debug 빌드 전용 개발용 인증 토큰 칸), 내 정보(닉네임 변경, 로그아웃), 지도(위치 권한 설명 → 허용 시 내 위치 기준, 거부 시 종로구 둘러보기 모드, 카테고리 필터, 마커를 누르면 상세).
- 서버 주소는 `BuildConfig.API_BASE_URL`(debug 기본 `http://10.0.2.2:8080/`, `-PapiBaseUrl`로 변경). 평문 HTTP는 debug 빌드의 `10.0.2.2`와 `localhost`에만 허용한다. 에러 코드를 한국어 문구로 바꾸는 곳은 한 파일(`util/ErrorMessages`)이다. 토큰은 로그에 남기지 않는다. 재발급 흐름은 없고 AUTH401을 받으면 토큰을 지우고 로그인으로 보낸다.

### 샘플 데이터 (`feat/1-seed`, local 프로파일 전용)
- 종로구 장소 32곳(`V900`): 궁, 북촌, 인사동, 시장, 박물관, 카페 등. 궁과 큰 공원은 인증 300m/알림 400m, 나머지는 100/200m, 한옥 카페 2곳은 150점, 뽈뽈 추천(CURATED) 12곳.
- 데모 계정 4개(`V901`): 정상 2, 가입 직후 1, 탈퇴 1. 비밀번호는 개발용 가짜 값이며 BCrypt 해시로만 저장돼 있다.
- `docs/local-demo.md`에 로컬 실행 방법, 데모 계정, 개발용 인증 토큰 형식, 에뮬레이터 위치 설정을 적었다.
- 시드가 test 프로파일에 새어 들어가 테스트가 깨지는 문제가 있어 local의 H2 DB 이름을 `bbolbbol-local`로 분리했다.

## 에뮬레이터 검증(오케스트레이터, `Medium_Phone`, 서버 8095 포트)
- 로그인: 데모 계정으로 로그인 성공 → 위치 권한 설명 화면 → 시스템 권한 창 → 지도.
- 지도: OpenStreetMap 타일이 뜨고 서버가 내려준 장소가 마커로 표시된다. 마커를 누르면 경복궁 상세(HOT, 유적지, 주소, 도착 시 300P)가 서버 데이터대로 나온다.
- 내 정보: 이메일, 가입 방식, 가입일, 닉네임이 서버 데이터와 맞는다.
- 회원가입: 입력 중 이메일과 닉네임 중복 확인 API가 실제로 호출돼 "사용할 수 있는 …" 문구가 뜬다. 개발용 토큰으로 가입하면 자동 로그인되어 지도로 이동하고, 서버에서도 새 계정으로 로그인된다(userId 5, `isNewUser: true`).
- 확인한 것은 이 흐름뿐이다. 닉네임 변경, 가입 실패 문구, 위치 권한 거부 시 둘러보기 모드, 카테고리 필터는 이번에 직접 눌러 보지 않았다(단위 테스트만 확인).

## 앱과 서버 계약 확인
앱 에이전트는 사용자 도메인이 끝나기 전에 사용자 API 형식을 잠정 계약으로 읽고 만들었는데, 통합 후 로그인, 가입, 내 정보, 중복 확인이 모두 실제 서버와 맞게 동작했다. 필드 이름이 달라서 생기는 문제는 발견하지 못했다.

## 알아둘 점, 결정이 필요한 것
- **가입 화면의 이메일:** 서버 가입 요청에 이메일이 없다(이메일은 인증 토큰에 묶임). 이메일 인증 방식(쟁점 2)이 정해지면 가입 화면을 다시 정해야 한다. 지금 release 빌드에서는 개발용 토큰 칸이 없어 가입할 수 없다(의도).
- **마커 아이콘이 기본 아이콘(손가락 모양)이다.** 디자인 미적용.
- **상태바 시계 글자가 흰색**이라 밝은 배경에서 잘 안 보인다(앱 테마 문제, 기능 아님).
- **지도 하단 "장소 19곳"**은 현재 화면 밖 장소도 포함한 개수다.
- **Notion 명세 원문 대조:** 앱 에이전트는 Notion 명세를 직접 읽지 않고 구현된 백엔드 코드를 계약으로 삼았다. 백엔드 쪽은 Notion 명세 대조를 마쳤으므로 간접적으로 맞춰져 있다.
- **API 24~29:** 최근 위치만 사용하고 실시간 위치 갱신은 API 30 이상에서만 쓴다.
- 앱 아이콘은 기본값이고 release 서명과 난독화는 설정하지 않았다.

## 미구현·미검증
- 도착 인증, 포인트, 랭킹, 카카오 로그인, 온보딩, 이메일 인증, 비밀번호 재설정, 재발급, 로그아웃 API 화면은 만들지 않았다(2단계 이후 또는 쟁점 대기).
- 기기 계기 테스트(`androidTest`)는 앱 데이터를 지우므로 돌리지 않았다.
- 실기기 확인은 하지 않았다. 실기기는 `10.0.2.2` 대신 PC의 LAN IP로 접속해야 한다.
- 카카오 수집 스크립트의 실제 호출, MySQL, Redis는 이전 보고와 같이 미검증이다.

## 정리되지 않은 것
- 수정 에이전트가 띄운 서버(`local` 프로파일, 8080, PID 26596)가 아직 종료되지 않았다. 종료는 사용자가 하기로 했다(`taskkill /PID 26596 /F`). 에뮬레이터 확인에는 이 서버를 쓰지 않았다(8095 포트의 새 서버를 쓰고 종료함).
- 에뮬레이터(`Medium_Phone`)는 켜져 있다. 앱 데이터는 지우지 않았다.
